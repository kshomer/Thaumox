# Xray: VLESS + XHTTP + TLS на собственном домене — скрипт 07

## Предварительные требования

Порядок обязателен, каждый шаг опирается на предыдущий:

1. **Доменное имя** зарегистрировано у любого регистратора.
2. **Домен подключён к Cloudflare**, выпущен API-токен —
   [04. Подключение домена к Cloudflare](04-cloudflare-setup.md).
3. **Сервер (VPS)** со свободными портами `443` и `80` —
   [03. Требования и порядок подготовки](03-domain-prerequisites.md).

## Принцип работы

```
интернет ──► Caddy :443 ──┬── /<служебный путь>/… ──► Xray :8080 (внутренняя сеть Docker)
                          └── остальные пути ───────► сайт
```

**Caddy** принимает внешний HTTPS-трафик домена (сертификат Let's Encrypt с автопродлением)
и распределяет его:

- запросы к **служебному пути** перенаправляются в Xray (транспорт XHTTP);
- все остальные запросы обслуживаются как **сайт**.

Служебный путь формируется при каждой установке: шаблон вида `/api/v2/sync` дополняется
случайным сегментом. Путь входит в клиентские ссылки. Ответы Xray с кодом 4xx Caddy
заменяет страницей сайта, поэтому открытие служебного пути в браузере показывает сайт.

## Параметры, которые запросит установщик

1. **Подключение к серверу** — IP-адрес, порт SSH, пользователь, пароль.
2. **Домен и API-токен Cloudflare.** Токен проверяется через API Cloudflare до внесения
   изменений; если зоны для домена в аккаунте нет, установщик сообщает об этом сразу.
3. **Сетевые порты.** Нужны `443/tcp`, `443/udp` (HTTP/3) и `80/tcp` (перенаправление на
   HTTPS). Если порты заняты, установщик предлагает освободить их; за один проход можно
   снять несколько контейнеров.
4. **Служебный путь (path)** — предлагается сгенерированное значение, можно ввести своё
   (латинские буквы, цифры, `/ _ - .`).
5. **Веб-сайт** — два варианта:
   - **шаблонный сайт** — четыре учебные страницы о двоичном кодировании, HTML/CSS без внешних
     зависимостей;
   - **собственный сайт** — каталог с `index.html` или сам файл `index.html`. Перед
     загрузкой выводится сводка (число файлов, объём, содержимое верхнего уровня) и
     запрашивается подтверждение. Служебные файлы и каталоги (`.git`, `.svn`, `.hg`,
     `node_modules`, `.env`, `.DS_Store`) не загружаются.
6. **Пользователи** — количество и имена.

> Каталог сайта публикуется целиком: любой файл внутри становится доступен по HTTPS.
> Указывается каталог сайта, а не рабочий каталог проекта.

До экрана подтверждения сервер не изменяется.

## Сертификат

Сертификат выпускает `acme.sh` с проверкой **DNS-01 через API Cloudflare**: входящие
подключения к серверу для проверки не нужны. Автоматическое продление выполняет задание
cron, которое устанавливает `acme.sh`; после продления Caddy перезапускается.

API-токен сохраняется на сервере в `/root/.acme.sh/account.conf` — он нужен для
продления.

## Что появится на сервере

```
/opt/xray-tls-domain/
  ├── docker-compose.yml
  ├── config/
  │    ├── xray.json        # конфигурация Xray
  │    └── Caddyfile        # конфигурация Caddy
  ├── certs/
  │    ├── fullchain.pem    # сертификат                    (права 644)
  │    └── privkey.pem      # закрытый ключ                 (права 600)
  ├── site/                 # сайт
  ├── log/
  │    ├── xray/            # журналы Xray
  │    └── caddy/           # журналы Caddy
  └── users.txt             # UUID и клиентские ссылки      (права 600)
```

Контейнеры: `xray-tls-domain` и `caddy-tls`.

## Важная информация

**Служебный путь нельзя менять вручную.** Менеджер не перестраивает конфигурацию Caddy
под изменённый путь, и ручная правка нарушает работу соединения.

**Клиенты.** Подходят клиентские приложения на ядре Xray-core. Ядро sing-box транспорт
XHTTP не поддерживает — для таких клиентов подходят конфигурации
[01](01-xray-reality-tcp.md) или [06](06-singbox.md).
