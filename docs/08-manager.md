# Менеджер — скрипт 00

`00-manager.sh` — менеджер для администрирования установленных конфигураций Xray и
sing-box. Конфигурация wg-easy управляется через собственную веб-панель.

---

## Запуск

Порядок установки — см. [10. Установка](10-installation.md). Скрипт менеджера —
`00-manager.sh`.

Менеджер запрашивает IP-адрес, порт SSH, пользователя и пароль, находит установки на
сервере и, если их несколько, предлагает выбрать одну. Дальше — меню из двенадцати
пунктов.

---

## Пункты меню

| № | Пункт | Что делает |
|---|---|---|
| 1 | **Пользователи и ссылки** | читает конфигурацию с сервера и показывает клиентские ссылки |
| 2 | **Добавить пользователя** | новый UUID; конфигурация применяется атомарно, контейнер перезапускается |
| 3 | **Удалить пользователя** | удаление пользователя с подтверждением |
| 4 | **Сменить SNI** | меняет имя целевого узла Reality или имя в самоподписанном сертификате (Hysteria2, TUIC). Недоступно для конфигурации с доменом |
| 5 | **Проверить статус** | контейнеры, последние строки журнала, потребление CPU и памяти |
| 6 | **Перезапустить** | перезапуск контейнера с проверкой, что время старта действительно изменилось |
| 7 | **Версия ядра** | показывает установленную версию, новейшую в реестре и стабильный релиз; позволяет перейти на другую |
| 8 | **QR-код** | ссылка в терминал, QR-код на экран и, по желанию, в PNG-файл |
| 9 | **Генерировать JSON** | клиентский профиль в формате sing-box или Xray-core — в зависимости от установки |
| 10 | **Сквозная проверка** | запускает на сервере временный клиент и проверяет фактическую передачу данных |
| 11 | **Файлы и команды** | где что лежит на сервере и как управлять вручную |
| 12 | **Удалить установку** | с сохранением каталога или полностью, с отдельным подтверждением |

---

## Подробнее

**Смена SNI (4).** Перед применением имя проверяется: наличие в DNS, ответ по TLS 1.3 и
HTTP/2, затем пробное Reality-соединение. Для Hysteria2 и TUIC перевыпускается
самоподписанный сертификат. Если применить конфигурацию не удалось, прежняя пара
ключ–сертификат возвращается и сервис поднимается снова.

**Версия ядра (7).** Номер стабильного релиза запрашивается у GitHub при каждом запуске.
Понижение версии требует отдельного подтверждения. Если контейнер не поднялся на новой
версии, выполняется откат, и его итог проверяется по фактически запущенному образу, а
не по факту выполнения команд.

**Генерация JSON (9).** Формат зависит от установки:

| Установка | Формат профиля |
|---|---|
| VLESS + Reality поверх TCP, любой протокол sing-box | sing-box 1.12+ |
| XHTTP и конфигурация с доменом | Xray-core |

У ядра sing-box нет транспорта XHTTP, поэтому для таких установок формируется профиль
Xray-core. В обоих форматах доступны два варианта маршрутизации:

- **весь трафик через туннель**;
- **раздельная маршрутизация (split tunneling)**.

После запуска профиля Xray-core клиент слушает SOCKS `127.0.0.1:10808` и HTTP
`127.0.0.1:10809`.

**Сквозная проверка (10).** Проверяется не открытый порт, а фактическая передача данных:
на сервере запускается временный клиент, собранный из выданной ссылки, и выполняет
HTTPS-запрос через установленное соединение. Успешным считается только ответ `HTTP 204`.
Проверка запускается автоматически после смены SNI и после смены версии.

**Удаление (12).** Перед подтверждением показывает, что именно будет удалено. Вариант с
сохранением переносит каталог в `<каталог>.bak.ДАТА`. Полное удаление снимает также
резервные копии, образы и, для конфигурации с доменом, `acme.sh` целиком
(`/root/.acme.sh`: сертификат, токен Cloudflare, задание cron).

## Куда сохраняются файлы

QR-коды (PNG) и клиентские профили (JSON) сохраняются в каталог `vless-json` внутри
текущего рабочего каталога терминала. При запуске из домашнего каталога это
`~/vless-json`.
